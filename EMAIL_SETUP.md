# Подтверждение email на SYUCAI

Письма отправляются через Resend. Начать можно с бесплатного тарифа; актуальные лимиты и условия смотрите на https://resend.com/pricing. Платная подписка для подключения кода не требуется.

## Подключение к рабочему сайту

1. Создайте аккаунт на https://resend.com и подтвердите свой адрес.
2. Resend → Domains → Add domain: добавьте `syucai.me`.
3. Скопируйте DNS-записи, которые выдаст Resend, в Cloudflare → **syucai.me → DNS → Records**. Тип, имя, содержимое и приоритет берите из Resend: значения DKIM и серверы зависят от вашего подключения. Сохраните существующую запись Worker для сайта. Дождитесь статуса Verified в Resend.
4. Resend → API Keys: создайте ключ с разрешением отправки писем для нужного домена.
5. Cloudflare → **Workers & Pages → syucai → Settings → Variables and Secrets**: добавьте **Secret** `RESEND_API_KEY`. Это настройки самого Worker, **не Variables and secrets в разделе Builds**. Значение ключа храните в менеджере паролей; не отправляйте его в чат и не коммитьте.
6. При необходимости задайте переменную `EMAIL_FROM`: по умолчанию используется `SYUCAI <noreply@syucai.me>`. Адрес должен принадлежать подтверждённому в Resend домену. `PUBLIC_SITE_URL` по умолчанию — `https://syucai.me`; при изменении разрешён только HTTPS.
7. Примените настройки Worker кнопкой Save/Deploy, которую показывает Cloudflare. В `/admin` → Google и настройки появится состояние «Ключ сервиса отправки писем добавлен». Это подтверждает наличие ключа, но не заменяет тест реальной доставки.
8. Войдите в личный кабинет пользователя или кабинет мастера и нажмите «Отправить письмо» / «Отправить письмо повторно». Перейдите по ссылке в почте и нажмите «Подтвердить email». В кабинете появится «Email подтверждён».

Не нужно менять тариф Cloudflare или покупать отдельный почтовый ящик, чтобы отправлять через Resend после подтверждения домена. Покупка почтового ящика для получения ответов — отдельная задача. Адрес `noreply@syucai.me` используется как отправитель, а не как созданный этим приложением почтовый ящик.

## Поведение сайта

- Регистрация создаёт аккаунт и запрашивает отправку письма. Кабинет, черновик и существующие права доступа сохраняются, даже если почтовый сервис ещё не подключён или временно недоступен. Неподтверждённый адрес явно отмечен в кабинете и в админ-панели.
- Фраза об отправке показывается только после подтверждения приёма письма API Resend. Ответ API не гарантирует доставку во входящие: проверяйте журнал отправок Resend при проблемах с почтой.
- Повторное письмо можно запросить не чаще раза в минуту; действует дополнительный часовой лимит. Повторная отправка не аннулирует предыдущую ещё действующую ссылку. После подтверждения все ссылки этого аккаунта становятся недействительными.
- Ссылка действует 24 часа. На сервере хранится только SHA-256 хеш случайного 256-битного токена. В URL используется fragment `#token=…`, который не передаётся серверу при открытии страницы. Страница очищает адрес и подтверждает email отдельным POST после нажатия кнопки. Аналитика и Google-скрипт на этой странице не запускаются.
- Подтверждение адреса не выполняет вход в аккаунт и не меняет активную сессию. Поэтому ссылку можно открыть на другом устройстве без автоматической авторизации.
- Кабинет обновляет статус после возвращения во вкладку и периодически, пока она видима. Подтверждённый адрес больше не предлагает повторную отправку.
- Старые аккаунты остаются доступны, а опубликованные профили не снимаются с публикации. Их владельцы могут подтвердить email из кабинета. Подтверждение не меняет дату регистрации и не начинает пробный период заново.
- Ключ Resend, адреса получателей, текст писем и секреты ссылок не записываются в прикладные логи. Email и содержание письма передаются почтовому провайдеру для доставки; это отражено в странице приватности.

## Проверки

Unit-тесты проверяют реальные SQL-операции с временной SQLite-базой, одноразовое подтверждение, сроки, хеширование, ограничения повторной отправки, ошибки провайдера и отсутствие автоматического входа. API почтового провайдера подменяется, реальные письма в тестах не отправляются.

Браузерные тесты проверяют статус, повторную отправку, изменение статуса после возвращения в кабинет, кнопку подтверждения и отсутствие токена в сетевых URL и аналитике. Реальную доставку нужно проверить после настройки домена и ключа Resend.

Подтверждение раздельное для профиля мастера и пользователя. Один email допустим в обоих разделах; письма и ссылки обозначают, какой профиль подтверждается. Переход по ссылке одного профиля не подтверждает второй. Для повторной отправки войдите именно в нужный раздел.

## Восстановление пароля по коду

На вкладке «Вход» в `/cabinet` и `/account` доступна кнопка «Забыли пароль?». Используется уже настроенный Resend и тот же отправитель; новые секреты не нужны. Письмо содержит шестизначный код, а не ссылку. Код действует 10 минут, на его проверку даётся пять попыток. Повторный запрос — через минуту, не больше пяти запросов на один email в выбранном разделе за час, дополнительно действует лимит по IP. В рабочем Worker отправка выполняется через `waitUntil`, чтобы время ответа не раскрывала наличие аккаунта. Ошибка отправителя не раскрывается по конкретному адресу; запись сохраняется, поскольку письмо после тайм-аута может всё же дойти.

После кода сайт показывает два поля нового пароля с отдельными кнопками просмотра. Сохранение автоматически открывает соответствующий кабинет. Смена пароля и отзыв прежних сеансов действуют только в выбранном разделе; другой профиль на том же email остаётся независимым. Успешный код подтверждает email только этого профиля. Не сообщайте коды оператору и не публикуйте их в журналах или Google-таблицах.
