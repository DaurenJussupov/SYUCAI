# SYUCAI

Минималистичный сайт на русском: расчёты по имени и дате рождения, каталог мастеров, личные кабинеты, документы, отзывы и обращение в WhatsApp. Белый интерфейс использует локально размещённый Manrope, компактные поля и меню в бургере на всех экранах. Frontend — Vite + JavaScript; backend — Cloudflare Worker, D1 и приватный R2.

## Локальный запуск

Нужен Node.js 22.12+ (в этой среде проверен Node 24).

```sh
npm ci
npm run build
npm run db:local
npm run preview
```

Wrangler запускает **полное приложение**, включая регистрацию и файлы, на порту 8787. Никакой авторизации Cloudflare для локальной работы не нужно. Для редактирования frontend можно дополнительно запустить `npm run dev`: Vite проксирует `/api` в Worker на 8787.

В ограниченной облачной среде используйте доступные для записи каталоги:

```sh
export npm_config_cache=/workspace/.npm-cache
export XDG_CONFIG_HOME=/workspace/.config
export WRANGLER_LOG_PATH=/tmp/syucai-wrangler.log
```

Не создавайте дополнительные worktree: текущая облачная задача уже изолирована. Работайте в существующем `/workspace/SYUCAI`.

## Проверки

```sh
npm test
npm run test:e2e
```

Playwright использует `/usr/bin/chromium`; переопределение — `CHROMIUM_PATH`. На другой машине установите Chromium или задайте путь. Браузерные тесты работают только с локальными D1/R2, используют отдельный каталог `.wrangler/test-state-<pid>` для каждого запуска и тестовый ключ администратора. Они проверяют расчёты, запрет кириллицы, мобильное меню, регистрацию, загрузку документов, приватность, модерацию, рейтинг, сообщение WhatsApp и выход из аккаунта. Тестовые анкеты снимаются с публикации в конце. Облако и реальные сообщения не затрагиваются.

## Развёртывание в Cloudflare

Это **Workers со Static Assets**, а не статический Pages-only проект: для кабинетов нужны Worker, D1 и R2. Требуется аккаунт Cloudflare с доступным R2 (может потребоваться включить R2 и billing). Не делайте R2 bucket публичным.

Cloudflare Workers Builds уже подключён к GitHub и использует `npx wrangler deploy`. В `wrangler.jsonc` задан custom build: он собирает frontend, затем в авторизованной сборке создаёт или переиспользует D1 `syucai` и приватный R2 `syucai-files`, применяет migrations и только после этого разрешает публикацию Worker. Wrangler автоматически находит ID D1 по имени. Задавать нулевой ID нельзя.

Токен сборки должен иметь Workers Scripts Edit, D1 Edit, Workers R2 Storage Edit и доступ к выбранному аккаунту. R2 должен быть включён в аккаунте. Ключи не коммитятся. Если прав или R2 нет, сборка останавливается с ошибкой; это нужно исправить в настройках Cloudflare.

При деплое с локальной машины авторизуйте CLI и передайте `CLOUDFLARE_API_TOKEN` через защищённое окружение, затем выполните `npm run deploy`. Схема применяется только в среде с этим токеном. Для локального dry run без изменения ресурсов:

```sh
SYUCAI_SKIP_REMOTE_SETUP=1 npx wrangler deploy --dry-run
```

После первого деплоя задайте `ADMIN_TOKEN` в Worker → Settings → Variables and Secrets (тип Secret) или через `npx wrangler secret put ADMIN_TOKEN`. Это отдельный секрет для проверки анкет, а не API token Cloudflare. Сохраните его в менеджере паролей. Без него мастер может подать анкету, но администратор не сможет её опубликовать.

Для собственного домена в Worker → Settings → Domains & Routes подключите `syucai.me` после проверки его DNS-зоны. Рабочий адрес `*.workers.dev` выдаёт Cloudflare при успешной публикации; его нельзя предсказать из названия репозитория.

## Регистрация Анары и модерация

1. Анара открывает `/account`, регистрируется по email и паролю (10+ символов).
2. Загружает фото и минимум один диплом, указывает имя, обязательную страну, любой город, квалификацию, описание и номер WhatsApp с кодом страны, без пробелов. Нажимает «Сохранить и отправить на проверку».
3. Владелец открывает `/admin` и вводит `ADMIN_TOKEN`. Ключ создаёт отдельную HttpOnly-сессию на 8 часов и не сохраняется в localStorage. Панель показывает также незавершённые анкеты и загруженные файлы.
4. Администратор скачивает фото/дипломы, проверяет анкету и нажимает «Опубликовать» или «На доработку».
5. Опубликованный профиль появляется в поиске. Изменения анкеты или новые файлы снимают публикацию до повторной проверки.

Для локальной проверки администратора можно создать **игнорируемый** `.dev.vars` с `ADMIN_TOKEN` или запустить `npx wrangler dev --var ADMIN_TOKEN:<локальный-ключ>`. Для production используйте исключительно `wrangler secret put`.

Отзывы доступны после регистрации/входа. Один аккаунт может оставить один отзыв на мастера; отзыв на самого себя запрещён. Нужны подтверждённый email и документ консультации. Отзыв публикуется после проверки модератором или администратором. Рейтинг — среднее оценок опубликованных отзывов с проверенным подтверждением.

## Расчёты и исходные материалы

Оригиналы пользователя сохранены в `references/artifacts/`. Калькулятор даты заменён новым оригиналом `den-syucai.html` (сохранён как `references/artifacts/birth.html`). Он показывает личный и общий день на текущую календарную дату браузера, рекомендации, числа сознания и миссии. Дата расчёта явно указана на странице. Личный день считается по цепочке личный год → личный месяц → личный день; общий день — по цифрам сегодняшней даты. Формулы и все трактовки из исходников перенесены в `src/birth-data.json`, `src/name-data.json`; тест проверяет полное совпадение справочных данных с исходниками. Автоматическая транслитерация из оригинала намеренно заменена проверкой латиницы по требованию пользователя. Допускаются A–Z, пробелы, дефис и апостроф между словами; цифры и другие алфавиты отклоняются.

Главная содержит два поля, кнопку «Рассчитать» и небольшой логотип с навигацией. Кнопка и Enter запускают расчёт для одной даты, одного имени либо обоих заполненных полей. Автоматического перехода при вводе нет. Все заполненные поля проверяются; некорректная дата или имя не игнорируются. Дата и имя не отправляются на сервер и не сохраняются в localStorage. После перезагрузки их нужно ввести заново.

Оригинальный логотип пользователя хранится без изменений в `public/logo.PNG` и используется в шапке и как favicon. Регистр расширения `.PNG` важен для Cloudflare. Размер в шапке — 64 × 64 px на компьютере и 56 × 56 px на телефоне; пропорции сохраняются.

## География

Страна выбирается отдельно по стабильному коду ISO 3166-1; названия стран локализуются через Intl.DisplayNames и сортируются по языку интерфейса. Город вводится свободно на любом языке (до 120 символов); справочник `shared/cities.js` служит только подсказкой. New York, new-york и Нью-Йорк распознаются как один известный город. Миграция `0005_world_locations.sql` сохраняет старые анкеты и добавляет `city_name`, `country_code`, `coordinates_known`. Поля страны и города сохраняются в черновике, админ-панели и Google-таблице.

Поиск принимает `country_code` и необязательный `city_name`; без города показывает всех опубликованных мастеров страны. Старый запрос `?city=almaty` сохраняет совместимость. Сначала выводится указанный город, затем другие города той же страны. Расстояние рассчитывается только при наличии известных координат у обеих сторон; для свободно введённых городов оно не выдумывается и отображается «В выбранной стране». Неизвестные координаты помечаются `coordinates_known=0`, публичные API возвращают `lat/lon: null`. Геокодер и геолокация не подключаются; имя и дата рождения не передаются внешним службам. В WhatsApp можно указать любой город и страну.

## Данные и ограничения перед публичным запуском

- В D1 хранятся аккаунты, профили, отзывы, хеши сессий. Пароли — PBKDF2-SHA256 с уникальной солью и 100000 итераций; сессии — HttpOnly, SameSite=Lax и Secure на HTTPS, срок 7 дней. Для входа, регистрации, отзывов и файлов есть ограничение частоты. Изменяющие запросы проверяют Origin.
- R2 закрыт. Документы доступны только владельцу и администратору; публичными становятся только одобренные фото. Загружаемые форматы/сигнатуры и лимит 5 МБ проверяются. До 5 документов на аккаунт. Автоматическая антивирусная проверка не подключена: администратору нужно открывать документы безопасным просмотрщиком.
- Подтверждение email и повторная отправка доступны после подключения Resend. Восстановление пароля, остальные почтовые уведомления, самостоятельное удаление аккаунта и автоматическая модерация отзывов не реализованы. Пароль нужно сохранить. Отзывы проверяются и скрываются через админ-панель; ручная работа с D1 нужна только для операций, которых ещё нет в интерфейсе. Для production рекомендуется Turnstile и почтовый провайдер для подтверждения/сброса пароля.
- В `/privacy` указан подтверждённый владельцем контакт temapluskz@gmail.com. До публичного сбора анкет уточните юридические сведения об операторе, условия обработки и срок хранения.
- При запросе удаления проверьте D1, R2 и копии в Google Drive/Sheets. В D1 удаление требует очистки связанных отзывов, записей файлов, черновиков и таблиц синхронизации до удаления аккаунта. Не удаляйте только строку аккаунта: внешние ключи требуют последовательной очистки. Сначала подготовьте экспорт и точный перечень связанных данных.
- `/admin` показывает аккаунты и анкеты с пагинацией по 50 записей; поиск и фильтр действуют на текущей странице. Отзывы в профиле — до 100 последних, средняя оценка считается по всем опубликованным отзывам.
- Рабочие ключи и реальные дипломы не входят в репозиторий. В GitHub попадают только исходники и migrations. Демонстрационные мастера и отзывы не добавляются в рабочую базу.

Раздел «О SYUCAI» использует тексты института, переданные владельцем, и приложенный биографический слайд. По подтверждению владельца сайт принадлежит институту; текст изложен от его лица. Сведения о званиях, наградах и регистрации основаны на переданных материалах; независимая проверка не заявляется. Происхождение материалов описано в `references/about-sources.md`.


## Языки

Переключатель слева от бургера содержит русский и 33 других языка. Используются локальные SVG-флаги (flag-icons, MIT), коды и названия языков. Список сортируется по алфавиту названий в текущем языке, доступен поиск. Молдавский обозначен MD и соответствует румынскому варианту Молдовы (`ro-MD`). Татарский использует флаг России с кодом TAT. Ингушский язык удалён из списка выбора. Для арабского и персидского включён RTL. Выбор хранится локально в `syucai.language`.

`npm run i18n:extract` собирает статические сообщения интерфейса, ошибки и трактовки из исходников в `src/i18n/source.json`. `npm run build` собирает frontend; в авторизованной сборке Cloudflare затем генерирует статические каталоги `dist/i18n/*.json` машинным переводом через публичный GET-интерфейс Google (`client=gtx`) с основным адресом `translate.googleapis.com` и резервным `translate.google.com`. Ключи и введённые пользователем данные в эти запросы не входят: отправляются только тексты из репозитория. Просмотр сайта загружает перевод с того же Worker и не обращается к внешнему переводчику. Описания мастеров и отзывы сохраняют язык автора; формулы не переводятся и не меняются.

Локальная сборка по умолчанию не обращается к переводчику. В Cloudflare Workers Builds генерация включается по `WORKERS_CI`, даже если токен авторизации не передан как `CLOUDFLARE_API_TOKEN`. Для реального формирования каталогов можно задать `SYUCAI_BUILD_TRANSLATIONS=1` в окружении с разрешённым HTTPS-доступом к `translate.googleapis.com` и `translate.google.com`. При повторном production build готовые каталоги берутся из предыдущей версии Worker. Если интерфейс изменился, переводы совпадающих исходных сообщений переиспользуются после проверки placeholders; сервису отправляются только новые строки. Доступ к `syucai.alphalab-kz.workers.dev` нужен сборщику для кеша, но ошибка кеша не блокирует повторный перевод.

Сервис машинного перевода может не поддерживать отдельные редкие языки или ограничивать частоту. Статусы сохраняются в `dist/i18n/manifest.json`. Ошибка обновления не удаляет готовые переводы: сборщик и браузер переиспользуют проверенные записи по точному исходному тексту независимо от общего sourceHash и старого статуса каталога. Для неполного перевода записывается статус `partial`; язык доступен, а новые строки временно остаются на русском с явным уведомлением. При полном отсутствии подходящих переводов выбор оставляет текущий язык и показывает ошибку. Кнопки языков не отключаются по ошибочному или устаревшему manifest: загрузку можно повторить. Производственная сборка без единого пригодного иностранного каталога завершается ошибкой и не публикует замену только на русском. В переводах машинного качества (особенно редких языков) нужна вычитка носителями. Машинные каталоги можно сохранить в `translations/cache/<locale>.json` для работы без сети; из них берутся только совпадающие строки с сохранёнными placeholders. Чтобы заменить их редакторскими переводами, сохраните полный каталог с актуальными locale/sourceHash/status/translations в `translations/<locale>.json` (см. `translations/README.md`). Проверенный каталог имеет приоритет и работает без внешнего переводчика; неполный или устаревший останавливает сборку. Не добавляйте пароли и персональные данные в каталоги.

Browser-тесты языка используют синтетические каталоги и проверяют UI, сохранение ввода, переключение, RTL, поиск и восстановление сохранённых переводов после правок текста, повторную загрузку после сбоя и явную ошибку при пустом каталоге; они не проверяют качество машинного перевода. Unit-тесты проверяют все 34 записи, алфавит, flags, сохранность placeholders и обработку ограничений сервиса.


## Страница «МОЙ КАЛЕНДАРЬ»

Главная и меню содержат отдельный переход `/calendar`. Кнопка «Рассчитать» показывает только энергии: сознание/миссию для даты, число имени для названия, либо всё вместе. При наличии даты после энергий выводятся только два сегодняшних числа (личное и общее) и ссылка в календарь. Дневные рекомендации больше не выводятся перед энергиями. Общая кнопка поиска мастера располагается после содержимого каждой страницы, включая главную, календарь, результаты и каталог.

Оригинал нового файла сохранён в `references/artifacts/calendar.html`, значения дней — в `src/calendar-data.json`. Календарь использует формулы и тексты оригинала, отображает оба числа в каждой ячейке, позволяет выбрать день, месяц и год в диапазоне ±30 лет от текущего, перейти стрелками между месяцами и вернуться к сегодня. Для выбранной даты доступны подробные трактовки личного и общего дня; отдельного справочника дней 1–9 на странице нет. При переходе из главной или результатов дата рождения подставляется; при прямом входе её нужно указать. Введённая дата остаётся только в памяти вкладки. Выбранные дата и месяц сохраняются при смене языка.

Новые строки календаря включены в ту же систему 34 языков. Месяцы и дни недели форматируются через Intl для выбранного языка; числовые формулы остаются прежними. Существующие ограничения готовности машинных переводов сохраняются: локальные тесты проверяют механику на синтетических каталогах, а доступность реальных каталогов зависит от production build и сервиса перевода.

На главной «МОЙ КАЛЕНДАРЬ» расположен слева от «Рассчитать» в одном ряду. На странице календаря отдельной кнопки открытия нет: после ввода полной корректной даты календарь обновляется автоматически; некорректная дата показывает ошибку и скрывает старый результат. Enter также выполняет проверку.

Перед переходом по ссылке «МОЙ КАЛЕНДАРЬ» проверяется дата рождения. Пустая, невозможная, неполная или будущая дата блокирует переход; без даты показывается «введите дату рождения». Из других страниц пользователь попадает в главную форму для исправления даты. Прямой адрес `/calendar` по-прежнему открывает форму даты.

На сенсорных устройствах список языков не фокусирует поиск автоматически, а выбор месяца/года не фокусирует заново native select после его изменения. Мобильные поля имеют шрифт не менее 16px для предотвращения focus zoom в Safari; ручное масштабирование не ограничивается. Проверки в Chromium с эмуляцией телефона подтверждают состояние фокуса, размер шрифта и viewport; поведение системного меню Safari требует проверки на реальном iPhone.

## Google, модерация и аналитика

В `/admin` доступны анкеты и черновики, файлы, комментарии мастерам, проверка отзывов, аналитика за 7/30/90 дней и журнал действий. Автосохранение черновика не публикует профиль. Отзывы до обновления сохраняют свой опубликованный статус, новые ожидают проверки. В поиске показываются средний рейтинг, количество и фрагмент последнего опубликованного отзыва.

Раздел Google создаёт приватную таблицу и папку Drive, копирует анкеты/файлы через очередь и может создать ресурс GA4 в аккаунте владельца. Основные данные остаются в D1/R2. Подключение требует OAuth-клиента Google и секретов Worker; без авторизации реальные ресурсы не создаются. Подробные шаги: [GOOGLE_SETUP.md](GOOGLE_SETUP.md).

Собственная аналитика и Google Analytics запускаются только с согласием посетителя. Единый баннер cookies содержит кнопки «Принять cookies» и «Только необходимые», а мелкий текст под кнопками поясняет согласие на обработку данных для аналитики. Повторно открыть выбор можно через «Настройки cookies». Имена, даты рождения, результаты расчётов и тексты сообщений не входят в события. Сессии означают вкладки с согласием; переход в WhatsApp не подтверждает консультацию. Собственные события удаляются через 90 дней. Cron каждые 5 минут обрабатывает одну анкету в очереди Google и удаляет устаревшие события.

## Пароли, пробный период и продвижение

При регистрации пароль вводится дважды; совпадение обязательно проверяется в браузере и Worker. У каждого поля есть независимая кнопка просмотра. На форме входа также доступен просмотр пароля. Подтверждение пароля не сохраняется в базе.

На регистрации и в кабинете указаны первые три бесплатных месяца с даты создания аккаунта. В кабинете показана дата окончания: три календарных месяца, с корректным переносом конца месяца. Тариф после пробного периода находится на рассмотрении руководства. Автоматические списания, платёжная система и отключение профиля по окончании срока не подключены.

Кнопка «Поднять мою карточку в поиске» открывает выбор 1–3 дней с базовыми ставками 500 / 900 / 1 200 ₸. Итоговая цена, доступность и запуск согласуются администратором. API не принимает новые заявки более чем на 3 дня и не позволяет повторную заявку при ожидающем или активном продвижении. Старые активные сроки сохраняются; старые ожидающие заявки более 3 дней нельзя активировать. Автоматические счета, приём оплаты, ограничение 9 карточек на город и ротация позиций 1–3 относятся к следующему этапу; текущая ручная активация и отметка продвигаемой карточки сохранены. Полные условия размещения и льготное предложение до 21.02.2027 включительно показаны в кабинете после регистрации/входа. На странице регистрации выводится только уведомление о доступности стоимости и условий после регистрации; автоматическое списание не выполняется.

Данные продвижения добавляются миграцией `0003_promotions.sql` без изменения существующих анкет. Подтверждение email добавляется миграцией `0004_email_verification.sql`. ## Личный кабинет, подтверждённые отзывы и модераторы

Миграция `0006_members_moderation_blog.sql` добавляет имя аккаунта, добровольную подписку, роль модератора, подтверждения консультаций и блог. `/cabinet` — регистрация пользователя (имя, email, пароль с повтором), подтверждение email через действующий Resend, управление подпиской и история отзывов. Регистрации пользователя и мастера независимы: один email можно использовать по одному разу в каждом разделе. В каждом разделе свои пароль, подтверждение email и сессия.

Новый отзыв требует подтверждённого email и файла PDF/JPG/PNG до 5 МБ. Документ хранится отдельно от дипломов в приватном R2; доступен автору, модератору и администратору, но не мастеру и не посетителям. До проверки отзыв и оценка не публикуются. Модератор открывает документ и явно подтверждает консультацию; только затем отзыв учитывается в рейтинге и превью. Замена текста/оценки/подтверждения возвращает отзыв на модерацию. Старые тексты сохраняются, но отзывы без проверенного документа не влияют на рейтинг; автор может дополнить их в профиле мастера.

Администратор → «Модераторы»: найти зарегистрированный email и назначить роль. В личном кабинете появится ссылка `/moderator`. Модератору доступны отзывы с подтверждениями, создание/редактирование/публикация собственных новостей и модерация всех комментариев блога. Профили, дипломы, настройки, аналитика, продвижение, подписчики и назначение ролей закрыты. Отзыв роли действует сразу, без повторного входа. Администратор может редактировать все новости. Публичный блог — `/blog`; черновики не выдаются публичными API. Текст новости выводится как текст, HTML не выполняется.

Администратор → «Подписчики»: только добровольно подписавшиеся пользователи с подтверждённым email, доступен CSV. Рассылки автоматически не отправляются при регистрации или публикации новости; для отдельной кампании используйте актуальный список и согласованный текст. Пользователь может отозвать подписку в кабинете. Письмо подтверждения email отправляется при регистрации независимо от выбора рассылки.

Интерфейс включает монгольский язык `mn` с флагом Монголии; список языков сортируется по выбранному языку.

## Раздельные регистрации и обсуждения блога

`0007_separate_profile_registrations.sql` сохраняет email-идентичность и все существующие внешние ключи, переносит данные входа в `account_registrations` с уникальностью `(account_id, registration_type)`. Значения `master` и `user` передаются в регистрации и входе явно; без типа старые запросы относятся к мастерам. Авторитетные пароль, роль, имя, подписка и подтверждение почты находятся в регистрации конкретного раздела. Старые одноимённые поля `accounts` оставлены только для совместимости миграции. Уже использованные ранее разделы сохраняют прежние данные и пароль.

Cookies `session_master` и `session_user` независимы, HttpOnly, SameSite=Lax, Secure на HTTPS. Выход завершает только выбранную сессию. Старый cookie `session` принимается только в исходном разделе и безопасно удаляется при переходе на новую сессию этого раздела. `/api/me` выбирает раздел по `X-Account-Type` или `?section=master|user`; в кабинете пользователя данные анкеты и дипломы мастера не выдаются. Защищённые API сами фиксируют раздел: документы/анкета/продвижение — master; отзывы/рассылки/модерация/комментарии — user. Подмена заголовка не меняет это правило. Ссылка подтверждения хранит тип регистрации на сервере; её использование не подтверждает другой профиль с тем же email. Совпадающая email-идентичность также не позволяет обойти запрет отзыва о собственной карточке.

`0008_blog_interactions.sql` добавляет лайки (один на пользователя), комментарии, ограничения и необязательные изображения JPG/PNG/WebP до 5 МБ. Комментарии публикуются сразу и выводятся только внутри статьи после текста; в списке статей показываются счётчики. Для лайков и комментариев нужен подтверждённый профиль пользователя. Текст выводится буквально, HTML не выполняется. Модератор и администратор могут удалить любой комментарий, ограничить комментарии пользователя и снять ограничение. Срочный срок: 0–12 календарных месяцев плюс минимум 1 день; окончания месяцев корректно учитывают 29/30/31 число. Есть бессрочный вариант. Истёкшие ограничения перестают действовать автоматически; лайки, вход и отзывы о мастерах блокировкой комментариев не затрагиваются. Обычный модератор не блокирует другого модератора — это доступно администратору. Изображения черновиков доступны только автору-модератору и администратору.

## Восстановление пароля

`0014_password_recovery.sql`, `worker/password-recovery.js` и `src/password-recovery.js` добавляют цепочку `request → verify → complete` для пользователей и мастеров. Общая кнопка «Забыли пароль?» есть на обеих вкладках входа. Если email введён до нажатия, запрос отправляется сразу; иначе сначала появляется поле email. Шесть отдельных цифровых полей поддерживают вставку полного кода, автоматический переход и Backspace. Затем вводятся новый пароль и повтор с независимым просмотром; после сохранения выдаётся сессия нужного профиля.

Секреты: коды, challenge и reset-grant хранятся в виде хешей; grant передаётся только HttpOnly/SameSite=Strict cookie с ограниченным путём. Код — 10 минут / 5 попыток, grant — ещё 10 минут; повторная отправка аннулирует прежние коды/разрешения этого раздела. Частота ограничена атомарно по хешу email и по IP. Ответы не раскрывают, зарегистрирован ли адрес. Доставка рабочей почты вынесена в `waitUntil`; неуспех провайдера не выводит код в ответ или журнал. Записи и лимиты удаляются через сутки.

Сохранение выполняется транзакцией D1 с уникальной меткой завершения: повторный или конкурентный запрос не изменит пароль второй раз. Проверяется исходная версия пароля; отзываются все scoped-сессии выбранного профиля и относящиеся к нему legacy-сессии, другое направление остаётся доступным. Подтверждение почты и выгрузка контактов обновляются только после успешного завершения. Тесты провайдера используют подменённый Resend, браузерные проверки — изолированную локальную D1 и тестовую выдачу кода; production-backdoor и возврата кода через API нет.
