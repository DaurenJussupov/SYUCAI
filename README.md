# SYUCAI

Минималистичный сайт на русском: расчёты по имени и дате рождения, каталог мастеров, личные кабинеты, документы, отзывы и обращение в WhatsApp. Белый интерфейс использует локально размещённый Manrope, компактные поля и меню в бургере на всех экранах. Frontend — Vite + JavaScript; backend — Cloudflare Worker, D1 и приватный R2.

## Локальный запуск

Нужен Node.js 22.12+ (в этой среде проверен Node 24).

```sh
npm ci
npm run build
npm run db:local
npm run preview
```

Wrangler запускает **полное приложение**, включая регистрацию и файлы, на порту 8787. Никакой авторизации Cloudflare для локальной работы не нужно. Для редактирования frontend можно дополнительно запустить `npm run dev`: Vite проксирует `/api` в Worker на 8787.

В ограниченной облачной среде используйте доступные для записи каталоги:

```sh
export npm_config_cache=/workspace/.npm-cache
export XDG_CONFIG_HOME=/workspace/.config
export WRANGLER_LOG_PATH=/tmp/syucai-wrangler.log
```

Не создавайте дополнительные worktree: текущая облачная задача уже изолирована. Работайте в существующем `/workspace/SYUCAI`.

## Проверки

```sh
npm test
npm run test:e2e
```

Playwright использует `/usr/bin/chromium`; переопределение — `CHROMIUM_PATH`. На другой машине установите Chromium или задайте путь. Браузерные тесты работают только с локальными D1/R2, используют отдельный каталог `.wrangler/test-state-<pid>` для каждого запуска и тестовый ключ администратора. Они проверяют расчёты, запрет кириллицы, мобильное меню, регистрацию, загрузку документов, приватность, модерацию, рейтинг, сообщение WhatsApp и выход из аккаунта. Тестовые анкеты снимаются с публикации в конце. Облако и реальные сообщения не затрагиваются.

## Развёртывание в Cloudflare

Это **Workers со Static Assets**, а не статический Pages-only проект: для кабинетов нужны Worker, D1 и R2. Требуется аккаунт Cloudflare с доступным R2 (может потребоваться включить R2 и billing). Не делайте R2 bucket публичным.

Cloudflare Workers Builds уже подключён к GitHub и использует `npx wrangler deploy`. В `wrangler.jsonc` задан custom build: он собирает frontend, затем в авторизованной сборке создаёт или переиспользует D1 `syucai` и приватный R2 `syucai-files`, применяет migrations и только после этого разрешает публикацию Worker. Wrangler автоматически находит ID D1 по имени. Задавать нулевой ID нельзя.

Токен сборки должен иметь Workers Scripts Edit, D1 Edit, Workers R2 Storage Edit и доступ к выбранному аккаунту. R2 должен быть включён в аккаунте. Ключи не коммитятся. Если прав или R2 нет, сборка останавливается с ошибкой; это нужно исправить в настройках Cloudflare.

При деплое с локальной машины авторизуйте CLI и передайте `CLOUDFLARE_API_TOKEN` через защищённое окружение, затем выполните `npm run deploy`. Схема применяется только в среде с этим токеном. Для локального dry run без изменения ресурсов:

```sh
SYUCAI_SKIP_REMOTE_SETUP=1 npx wrangler deploy --dry-run
```

После первого деплоя задайте `ADMIN_TOKEN` в Worker → Settings → Variables and Secrets (тип Secret) или через `npx wrangler secret put ADMIN_TOKEN`. Это отдельный секрет для проверки анкет, а не API token Cloudflare. Сохраните его в менеджере паролей. Без него мастер может подать анкету, но администратор не сможет её опубликовать.

Для собственного домена в Worker → Settings → Domains & Routes подключите `syucai.me` после проверки его DNS-зоны. Рабочий адрес `*.workers.dev` выдаёт Cloudflare при успешной публикации; его нельзя предсказать из названия репозитория.

## Регистрация Анары и модерация

1. Анара открывает `/account`, регистрируется по email и паролю (10+ символов).
2. Загружает фото и минимум один диплом, указывает имя, город, квалификацию, описание и номер WhatsApp с кодом страны, без пробелов. Нажимает «Сохранить и отправить на проверку».
3. Владелец открывает `/admin` и вводит `ADMIN_TOKEN`. Ключ создаёт отдельную HttpOnly-сессию на 8 часов и не сохраняется в localStorage. Панель показывает также незавершённые анкеты и загруженные файлы.
4. Администратор скачивает фото/дипломы, проверяет анкету и нажимает «Опубликовать» или «На доработку».
5. Опубликованный профиль появляется в поиске. Изменения анкеты или новые файлы снимают публикацию до повторной проверки.

Для локальной проверки администратора можно создать **игнорируемый** `.dev.vars` с `ADMIN_TOKEN` или запустить `npx wrangler dev --var ADMIN_TOKEN:<локальный-ключ>`. Для production используйте исключительно `wrangler secret put`.

Отзывы доступны после регистрации/входа. Один аккаунт может оставить один отзыв на мастера; отзыв на самого себя запрещён. Новые отзывы публикуются администратором в разделе «Отзывы». Рейтинг — среднее опубликованных оценок. Подтверждение оплаты консультации не реализовано; это явно указано в форме.

## Расчёты и исходные материалы

Оригиналы пользователя сохранены в `references/artifacts/`. Калькулятор даты заменён новым оригиналом `den-syucai.html` (сохранён как `references/artifacts/birth.html`). Он показывает личный и общий день на текущую календарную дату браузера, рекомендации, числа сознания и миссии. Дата расчёта явно указана на странице. Личный день считается по цепочке личный год → личный месяц → личный день; общий день — по цифрам сегодняшней даты. Формулы и все трактовки из исходников перенесены в `src/birth-data.json`, `src/name-data.json`; тест проверяет полное совпадение справочных данных с исходниками. Автоматическая транслитерация из оригинала намеренно заменена проверкой латиницы по требованию пользователя. Допускаются A–Z, пробелы, дефис и апостроф между словами; цифры и другие алфавиты отклоняются.

Главная содержит два поля, кнопку «Рассчитать» и небольшой логотип с навигацией. Кнопка и Enter запускают расчёт для одной даты, одного имени либо обоих заполненных полей. Автоматического перехода при вводе нет. Все заполненные поля проверяются; некорректная дата или имя не игнорируются. Дата и имя не отправляются на сервер и не сохраняются в localStorage. После перезагрузки их нужно ввести заново.

Оригинальный логотип пользователя хранится без изменений в `public/logo.PNG` и используется в шапке и как favicon. Регистр расширения `.PNG` важен для Cloudflare. Размер в шапке — 64 × 64 px на компьютере и 56 × 56 px на телефоне; пропорции сохраняются.

## География

Справочник `shared/cities.js` содержит основные города Казахстана и ряд городов других стран. Поиск ограничивается той же страной и сортирует по расстоянию между центрами городов (формула гаверсинуса), сначала тот же город. Геолокация не запрашивается. Ближайшие мастера из другой страны не подмешиваются. Если город отсутствует, интерфейс предлагает ближайший из справочника в той же стране. Для широкого международного запуска расширьте справочник или подключите геокодер.

## Данные и ограничения перед публичным запуском

- В D1 хранятся аккаунты, профили, отзывы, хеши сессий. Пароли — PBKDF2-SHA256 с уникальной солью и 100000 итераций; сессии — HttpOnly, SameSite=Lax и Secure на HTTPS, срок 7 дней. Для входа, регистрации, отзывов и файлов есть ограничение частоты. Изменяющие запросы проверяют Origin.
- R2 закрыт. Документы доступны только владельцу и администратору; публичными становятся только одобренные фото. Загружаемые форматы/сигнатуры и лимит 5 МБ проверяются. До 5 документов на аккаунт. Автоматическая антивирусная проверка не подключена: администратору нужно открывать документы безопасным просмотрщиком.
- Email verification, восстановление пароля, почтовые уведомления, самостоятельное удаление аккаунта и автоматическая модерация отзывов не реализованы. Пароль нужно сохранить. Отзывы проверяются и скрываются через админ-панель; ручная работа с D1 нужна только для операций, которых ещё нет в интерфейсе. Для production рекомендуется Turnstile и почтовый провайдер для подтверждения/сброса пароля.
- В `/privacy` указан подтверждённый владельцем контакт temapluskz@gmail.com. До публичного сбора анкет уточните юридические сведения об операторе, условия обработки и срок хранения.
- При запросе удаления проверьте D1, R2 и копии в Google Drive/Sheets. В D1 удаление требует очистки связанных отзывов, записей файлов, черновиков и таблиц синхронизации до удаления аккаунта. Не удаляйте только строку аккаунта: внешние ключи требуют последовательной очистки. Сначала подготовьте экспорт и точный перечень связанных данных.
- `/admin` показывает аккаунты и анкеты с пагинацией по 50 записей; поиск и фильтр действуют на текущей странице. Отзывы в профиле — до 100 последних, средняя оценка считается по всем опубликованным отзывам.
- Рабочие ключи и реальные дипломы не входят в репозиторий. В GitHub попадают только исходники и migrations. Демонстрационные мастера и отзывы не добавляются в рабочую базу.

Тексты о SYUCAI описывают нумерологическую практику и не заявляют доказанность определения характера или будущего по числам. Раздел «О SYUCAI» использует тексты института, переданные владельцем, и приложенный биографический слайд. Сведения о званиях, наградах и регистрации отнесены к этим источникам; независимая проверка не заявляется. Происхождение материалов описано в `references/about-sources.md`.


## Языки

Переключатель слева от бургера содержит русский и 34 уникальных запрошенных языка. Используются локальные SVG-флаги (flag-icons, MIT), коды и названия языков. Список сортируется по алфавиту названий в текущем языке, доступен поиск. Молдавский обозначен MD и соответствует румынскому варианту Молдовы (`ro-MD`). Татарский, чеченский и ингушский используют флаг России с отдельными кодами TAT/CHE/ING. Для арабского и персидского включён RTL. Выбор хранится локально в `syucai.language`.

`npm run i18n:extract` собирает статические сообщения интерфейса, ошибки и трактовки из исходников в `src/i18n/source.json`. `npm run build` собирает frontend; в авторизованной сборке Cloudflare затем генерирует статические каталоги `dist/i18n/*.json` машинным переводом через публичный endpoint `translate.google.com`. Ключи и введённые пользователем данные в эти запросы не входят: отправляются только тексты из репозитория. Просмотр сайта загружает перевод с того же Worker и не обращается к внешнему переводчику. Описания мастеров и отзывы сохраняют язык автора; формулы не переводятся и не меняются.

Локальная сборка по умолчанию не обращается к переводчику. Для реального формирования каталогов можно задать `SYUCAI_BUILD_TRANSLATIONS=1` в окружении с разрешённым HTTPS-доступом к `translate.google.com`. При повторном production build готовые каталоги берутся из предыдущей версии Worker. Если интерфейс изменился, переводы совпадающих исходных сообщений переиспользуются после проверки placeholders; сервису отправляются только новые строки. Доступ к `syucai.alphalab-kz.workers.dev` нужен сборщику для кеша, но ошибка кеша не блокирует повторный перевод.

Сервис машинного перевода может не поддерживать отдельные редкие языки или ограничивать частоту. Статусы сохраняются в `dist/i18n/manifest.json`. Неудачный перевод **не выдаётся за готовый**: выбор такого языка не меняет текущий язык и показывает сообщение. Полноту каталога, числовые placeholders и sourceHash проверяет сборщик. В переводах машинного качества (особенно редких языков) нужна вычитка носителями. Чтобы заменить их редакторскими переводами, сохраните полный каталог с актуальными locale/sourceHash/status/translations в `translations/<locale>.json` (см. `translations/README.md`). Проверенный каталог имеет приоритет и работает без внешнего переводчика; неполный или устаревший останавливает сборку. Не добавляйте пароли и персональные данные в каталоги.

Browser-тесты языка используют синтетические каталоги и проверяют UI, сохранение ввода, переключение, RTL, поиск и явную ошибку при неготовом каталоге; они не проверяют качество машинного перевода. Unit-тесты проверяют все 35 записей, алфавит, flags, сохранность placeholders и обработку ограничений сервиса.


## Страница «МОЙ КАЛЕНДАРЬ»

Главная и меню содержат отдельный переход `/calendar`. Кнопка «Рассчитать» показывает только энергии: сознание/миссию для даты, число имени для названия, либо всё вместе. При наличии даты после энергий выводятся только два сегодняшних числа (личное и общее) и ссылка в календарь. Дневные рекомендации больше не выводятся перед энергиями. Общая кнопка поиска мастера располагается после содержимого каждой страницы, включая главную, календарь, результаты и каталог.

Оригинал нового файла сохранён в `references/artifacts/calendar.html`, значения дней — в `src/calendar-data.json`. Календарь использует формулы и тексты оригинала, отображает оба числа в каждой ячейке, позволяет выбрать день, месяц и год в диапазоне ±30 лет от текущего, перейти стрелками между месяцами и вернуться к сегодня. Для выбранной даты доступны подробные трактовки личного и общего дня; отдельного справочника дней 1–9 на странице нет. При переходе из главной или результатов дата рождения подставляется; при прямом входе её нужно указать. Введённая дата остаётся только в памяти вкладки. Выбранные дата и месяц сохраняются при смене языка.

Новые строки календаря включены в ту же систему 35 языков. Месяцы и дни недели форматируются через Intl для выбранного языка; числовые формулы остаются прежними. Существующие ограничения готовности машинных переводов сохраняются: локальные тесты проверяют механику на синтетических каталогах, а доступность реальных каталогов зависит от production build и сервиса перевода.

На главной «МОЙ КАЛЕНДАРЬ» расположен слева от «Рассчитать» в одном ряду. На странице календаря отдельной кнопки открытия нет: после ввода полной корректной даты календарь обновляется автоматически; некорректная дата показывает ошибку и скрывает старый результат. Enter также выполняет проверку.

Перед переходом по ссылке «МОЙ КАЛЕНДАРЬ» проверяется дата рождения. Пустая, невозможная, неполная или будущая дата блокирует переход; без даты показывается «введите дату рождения». Из других страниц пользователь попадает в главную форму для исправления даты. Прямой адрес `/calendar` по-прежнему открывает форму даты.

На сенсорных устройствах список языков не фокусирует поиск автоматически, а выбор месяца/года не фокусирует заново native select после его изменения. Мобильные поля имеют шрифт не менее 16px для предотвращения focus zoom в Safari; ручное масштабирование не ограничивается. Проверки в Chromium с эмуляцией телефона подтверждают состояние фокуса, размер шрифта и viewport; поведение системного меню Safari требует проверки на реальном iPhone.

## Google, модерация и аналитика

В `/admin` доступны анкеты и черновики, файлы, комментарии мастерам, проверка отзывов, аналитика за 7/30/90 дней и журнал действий. Автосохранение черновика не публикует профиль. Отзывы до обновления сохраняют свой опубликованный статус, новые ожидают проверки. В поиске показываются средний рейтинг, количество и фрагмент последнего опубликованного отзыва.

Раздел Google создаёт приватную таблицу и папку Drive, копирует анкеты/файлы через очередь и может создать ресурс GA4 в аккаунте владельца. Основные данные остаются в D1/R2. Подключение требует OAuth-клиента Google и секретов Worker; без авторизации реальные ресурсы не создаются. Подробные шаги: [GOOGLE_SETUP.md](GOOGLE_SETUP.md).

Собственная аналитика и Google Analytics запускаются только с согласием посетителя. Имена, даты рождения, результаты расчётов и тексты сообщений не входят в события. Сессии означают вкладки с согласием; переход в WhatsApp не подтверждает консультацию. Собственные события удаляются через 90 дней. Cron каждые 5 минут обрабатывает одну анкету в очереди Google и удаляет устаревшие события.
